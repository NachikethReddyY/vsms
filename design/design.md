# VSMS — Design Documentation

Visual Screening Management System · Landing page + event-operations dashboard prototype
Files: `designl.html` (landing), `designd.html` (dashboard), `prototype.html` (flow walk-through)

---

## 1. Product context

VSMS is an offline-capable web application for staff running community vision-screening
events. It replaces paper forms, manual queues, and delayed spreadsheet reporting. Staff
register participants, move them through screening stations, record results, identify
rule-based flags, send flagged participants to a reviewer, create referrals, and safely
save data while offline before synchronising later.

Participant flow:

```
Registration → Visual acuity → Refraction → Colour vision → Eye health → Clinical review / referral
```

Product rules the design must respect:

- Participants never create accounts. All identity is staff-mediated (search, QR event pass).
- The app never diagnoses. Language is always: "Flagged for reviewer assessment" or
  "Referral recommendation generated by screening rules." The final decision is always
  made by a reviewer.
- Offline is not failure. The correct tone is reassurance:
  "Saved safely on this device. Records will synchronise when the connection returns."
- Sync states: Saved offline · Pending sync · Syncing · Synced · Sync failed · Conflict
  requiring review.
- QR event passes reduce lookup friction; QR content never exposes clinical data.

## 2. Reference systems and what each contributes

This design synthesises four reference postures. Nothing is copied; each contributes one
discipline:

| Reference | Contribution |
|---|---|
| **Ollama** | **Simplicity.** The page reads like a well-set document, not a marketing surface. One idea per section, flat canvas, no decorative chrome, restraint as the brand. |
| **Framer** | **Main colours.** Monochrome foundation — strong ink/near-black on neutral surfaces, hierarchy carried by ink → muted contrast rather than by weight ramps or colour. A single accent, used scarcely. The dark theme's warm near-black surfaces. |
| **Cursor** | **Canvas, surface, text & hairlines.** Warm cream canvas (never pure white, never cool gray), warm near-black ink, three grades of hairline doing all structural work. **The AI-timeline signature:** muted pastel stage markers (peach, blue, lavender, mint, gold) scoped to journey visualisations only. **Semantic** green/red tones. |
| **Apple** | **Typography and spacing.** System-native type stack, weight 600 headlines with tight negative tracking, 17px landing body at 1.47 leading, generous section rhythm, hairline-only depth, one accent for every "click me" signal. |

The accent is **blue** — a calm, clinical blue (`#2563EB` light / `#93C5FD` dark), chosen as the single "click me" signal. The canvas stays warm cream and the ink stays warm near-black, so the blue reads as precise and operational rather than as a blue-grey wash. Inside the screening timeline a second, muted pastel blue (`#9FBBE0`) marks the Visual acuity stage; the accent blue and the pastel blue are distinct in saturation and role.

## 3. Visual principles

The interface is **operational tooling**, not marketing. It should feel like a precision
instrument: quiet, dense where it matters, generous where it helps.

1. **Simplicity before everything.** If an element can be removed without losing meaning,
   remove it. Structure, spacing and typography carry the design — not colour, not
   decoration, not component chrome.
2. **Monochrome foundation, one accent.** Surfaces and text are warm neutrals. A single blue accent marks interactivity: selection, focus, links, active states. Everything else that is coloured is semantic.
3. **Warm, not clinical-cold.** The canvas is warm cream, the ink is warm near-black.
   The system should feel like paper and print, not like a hospital terminal.
4. **Hairlines do the structural work.** 1px dividers separate everything. No drop
   shadows on cards, buttons, or text; no borders heavier than 1px except focus rings.
5. **One dominant surface.** The live queue is a continuous workspace, not a grid of
   cards. Cards appear nowhere in the dashboard.
6. **Semantic colour only.** Beyond the one accent, colour always means something:
   amber = review, orange = referral, red = urgent, green = complete/synced. If a colour
   carries no meaning, it is a neutral.
7. **Clinical trust in wording.** Plain, unhedged language in the NHS/GOV.UK tradition:
   state what happened, state what happens next, never imply a diagnosis.
8. **Offline is a first-class state**, surfaced calmly and persistently — never as an
   error.

Explicitly avoided: generic admin metric-card grids, nested cards, full-width coloured
metric strips, decorative gradients/glass/heavy borders, large status pills, tiny gray
text, consumer-wellness styling, government-portal styling, default component-library
appearance, AI-dashboard clichés, and blue-dominant admin palettes.

## 4. Design tokens

### 4.1 Typography

- **Stack (both pages):** `system-ui, -apple-system, "SF Pro Text", Inter, "Segoe UI",
  sans-serif`. On Apple platforms this resolves to SF Pro; elsewhere Inter (loaded via
  Google Fonts) is the near-exact metric match. No second typeface inside the app.
- **Code / IDs:** `ui-monospace, "SF Mono", Menlo, monospace` — only for participant IDs
  and QR/event codes where fixed-width alignment matters.
- **Weight ladder:** **400 / 600 only.** Weight 500 is deliberately absent (Apple
  discipline): body is 400, emphasis is 600. Hierarchy comes from size, tracking and
  ink-vs-muted contrast, not from weight ramps.
- **Tracking:** negative letter-spacing at display sizes (`-0.02em` at 40px+, `-0.01em`
  at 17–28px), zero below 14px. The tight display cadence is intentional; never apply
  it to captions.
- **Numerals:** `font-variant-numeric: tabular-nums` everywhere numbers align (wait
  times, counts, IDs, timestamps).

**Scale (app):**

| Token | Size / leading | Weight | Use |
|---|---|---|---|
| `t-micro` | 11px / 16px, +0.06em, uppercase | 600 | overlines, section labels |
| `t-caption` | 12px / 16px | 400 | secondary metadata, timestamps |
| `t-body` | 13px / 20px | 400 | row content, controls |
| `t-strong` | 14px / 20px | 600 | participant names, primary labels |
| `t-title` | 15px / 22px | 600 | workspace title |

**Scale (landing):**

| Token | Size / leading | Weight | Use |
|---|---|---|---|
| `t-display` | 56px / 1.07, −0.02em | 600 | hero headline |
| `t-headline` | 40px / 1.10, −0.02em | 600 | section headlines |
| `t-lead` | 21px / 1.4 | 400 | section leads |
| `t-body-l` | 17px / 1.47, −0.01em | 400 | body copy — 17px, not 16px |
| `t-caption-l` | 14px / 1.43 | 400 | captions, nav, footer |

### 4.4 Shape, elevation, motion

- **Radii:** 8px controls and inputs, 12px panels and the inspector, full pill
  (`9999px`) for the landing page's primary CTA and the in-app primary button.
  Nothing else. No 4px chips, no 16px+ cards.
- **Elevation:** hairline-only depth. No drop shadows on cards, buttons, rows, or text.
  The single exception: the inspector drawer and modal overlays on tablet get one soft
  shadow (`0 8px 30px rgba(38,37,30,0.12)`) so they read as floating over the workspace.
- **Hierarchy on dark** comes from surface steps (canvas → surface → surface-2), not
  from shadows or opacity tricks on white type.
- **Motion:** 120–160ms ease-out for state changes; none for layout. Press feedback on
  buttons is `transform: scale(0.97)`. Full `prefers-reduced-motion` support (all
  transitions and the press scale removed).

## 5. Dashboard architecture (`designd.html`)

### 5.1 Application shell

- `100dvh` app, no document-level horizontal scrolling at any breakpoint.
- **Sidebar:** 224px expanded / 64px collapsed rail, on `--canvas-soft`. Navigation
  scrolls internally; connectivity and profile stay pinned to the bottom.
- **Top command bar:** 52px, white `--surface`, 1px `--hairline` bottom. Contains event
  identity ("Northside Community Screening · Live"), global participant/command search,
  sync status, notifications, help, theme toggle, account. There is **no duplicate page
  header** below the bar.
- **Queue workspace:** fluid, dominant region on white `--surface`; scrolls internally.
- **Inspector:** 320px contextual panel on `--surface-2`; becomes an overlay drawer
  below 1100px; sidebar collapses to the 64px rail below 860px.

### 5.2 Sidebar

- Compact event switcher at top: event name + date, single chevron, no card chrome.
- Navigation: Dashboard, Participants, Live queue (18), Screening, Review & referrals
  (12), Sync centre (3), Reports, Settings.
- Active state: 2px accent indicator on the leading edge + faint `--accent-tint` —
  subtle, never a filled pill.
- Counts are small, right-aligned, tabular numerals, `--muted`.
- Bottom cluster (fixed): connectivity ("Connected · Synced 2 min ago" or offline
  equivalent) and the signed-in staff member with role. Separated from nav by one
  `--hairline`, nothing more.

### 5.3 Top command bar

Left: sidebar collapse control + event identity with a quiet "Live" marker (small green
dot + text, not a badge). Centre: global search ("Search participants, IDs, commands…")
with `/` shortcut hint, 8px radius, `--canvas` fill. Right: sync status ("Saved locally
· 3 pending"), theme toggle, notifications, help, account. All targets ≥ 44px where
operational.

### 5.4 Queue workspace

- Title row: **Live queue (18)** with an inline summary in `--muted`:
  `146 registered · 18 waiting · 72 complete · 12 require review · 3 pending sync`.
- Toolbar: row search, station filter, status filter, urgent-first toggle, queue menu
  (overflow). Compact 34px controls, 8px radius, `--hairline-strong` borders.
- The list is a **continuous surface** with 1px `--hairline-soft` row dividers — no row
  cards, no gaps.
- Rows are **62px** high. Columns: Participant · Station · Wait · Status · Action · More.
- Participant identity is dominant: 14px/600 `--ink` name; second line
  `VSMS-240719-035 · Queue 03` in 12px `--muted` tabular.
- Exactly **one visible row action** ("Start review", "Continue", "Check in"…) rendered
  as small ink text with a trailing chevron — not a button; everything else lives in the
  row overflow menu.
- Statuses are compact **icon + text**, coloured text only, no pills:
  Waiting (muted clock) · Screening (accent blue) · Review (amber) · Referral
  (orange) · Urgent (red) · Complete (green). Note: in-progress uses the one accent —
  there is no separate "active blue" in the system.
- Selected row: `--accent-tint` background + 2px leading accent indicator (inset, no
  layout shift). Never a bright fill.
- Urgent rows are **not red rows** — only the status text/icon takes the red treatment.

### 5.5 Participant inspector

Structure for the selected participant (Evelyn Ng):

1. **Identity:** name (600), `68 years · VSMS-240719-035`, current station
   ("Current station: Clinical review").
2. **Save state:** "Saved locally" in `--green` with the offline-reassurance caption:
   "Saved safely on this device. Records will synchronise when the connection returns."
3. **Screening timeline** *(the signature element)*: vertical rail with the muted pastel
   stage markers from §4.2 — Registration (peach) complete · Visual acuity (pastel blue)
   complete · Clinical review (blue ring, active) · Eye health (gold, pending).
   Completed stages are filled, the active stage is ringed in `--accent`, pending stages
   are hollow. The pastels appear **only here** — nowhere else in the app.
4. **Flag explanation** (amber-tinted panel, 1px amber hairline, plain wording):
   "Flagged for reviewer assessment. Distance acuity crossed the configured review
   threshold. Final decision made by reviewer."
5. **One prominent action:** solid `--accent` "Start review" button, full width, 40px,
   pill radius. Press state: `scale(0.97)`.
6. **Collapsible rows** (details/summary with chevrons, separated by `--hairline-soft`):
   Screening summary · Operational notes · Recent activity. No stacks of equal outline
   buttons, no card-like sections.

## 6. Landing page (`designl.html`)

Same token system, editorial register — Ollama's document simplicity set with Apple's
typography and rhythm:

1. **Nav** — 56px, wordmark left, four anchors, theme toggle, one ink pill CTA
   ("Open the prototype"). 1px `--hairline` bottom. No blur, no transparency games.
2. **Hero** — `--canvas` cream, 56px/600 headline at −0.02em tracking
   ("Run community vision screening without paper, queues, or guesswork."), 17px lead,
   one ink pill CTA + one text link. No hero illustration, no gradient, no grid
   gimmick — whitespace is the design.
3. **Field constraints strip** — offline-capable · role-based access · no participant
   accounts · WCAG 2.2 AA, as quiet inline facts separated by hairlines.
4. **01 / The problem** — three plain statements about paper, queues, and delayed
   reporting, separated by hairlines. Statements, not feature cards.
5. **02 / The event flow** — the six-station participant journey rendered with the
   **timeline pastel markers** (peach → blue → lavender → mint → gold → accent blue ring) —
   the landing page's one chromatic moment, matching the inspector's timeline.
6. **03 / Built for the field** — the offline promise with the six sync states listed
   verbatim as icon+text rows; QR event passes with the explicit "no clinical data in
   the QR" rule.
7. **04 / Roles** — the five staff roles, one line each, hairline-separated.
8. **Product preview** — a static, reduced mock of the live queue in a plain hairline
   frame, linking into the real prototype.
9. **CTA + footer** — one quiet dark band (`--canvas` dark values, ink text, single
   light pill CTA), then a `--canvas` footer with `--muted` fine print.

Tone rules mirror the app: no stock-icon feature cards, no pill badges, no social-proof
strip, no gradient text, no coloured section backgrounds. The page earns attention with
typography, spacing, the warm canvas, and one chromatic timeline moment.

## 7. Accessibility (WCAG 2.2 AA)

- Text contrast ≥ 4.5:1 in both themes; `--accent` is darkened/lightened per theme to
  hold AA for text-on-surface uses.
- Visible focus: 2px `--accent` outline with 2px offset on all interactive elements.
- Keyboard: rows are focusable listbox options; `↑/↓` moves, `Enter` selects; inspector
  collapsibles are native `<details>`; drawer traps and restores focus; `Esc` closes.
- Touch: operational targets ≥ 44px on tablet breakpoints.
- `prefers-reduced-motion` removes all transitions and the button press scale.
- Statuses are never colour-only — each has an icon and text label.
- The timeline pastels are decorative markers on top of text labels; stage meaning is
  always carried by the label text, never by the pastel alone.
