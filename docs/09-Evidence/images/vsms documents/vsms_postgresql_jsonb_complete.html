Why separate rows?

  • Each station is a separate screening transaction.
  • Every row has its own primary key, timestamp, rule version, and audit record.
  • The same participant code links all rows together.
  • Queries can combine all station results for one participant.

Query all station rows

SELECT
  screening_id,
  participant_code,
  event_id,
  station_id,
  test_results,
  overall_flag,
  screened_at
FROM vsms.screening_results
WHERE participant_code = 'P10021'
  AND event_id = 'EVT001'
ORDER BY screened_at;

Advantages of PostgreSQL JSONB

Flexible schema

Different stations store different test structures without changing the table.

Powerful querying

Use →, →>, #>>, @>, ?, JSONPath, and standard SQL together.

Indexable

GIN and expression indexes improve searches on nested data.

Auditable

Store the original input, rule version, matched conditions, and final result.

Future-proof

Add new tests and properties without frequent schema migration.

Partial updates

Update one nested value using jsonb_set without replacing unrelated data.

Hybrid model

Keep IDs and relationships relational while test details remain flexible.

Analytics-ready

Aggregate by participant, event, station, flag, and nested test outcomes.
